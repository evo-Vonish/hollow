# 一、项目概述

我们并不准备制作一个传统意义上的"搜索引擎"。

也不准备制作一个普通浏览器。

更不是一个简单的 AI Chat 套壳工具。

本项目真正的目标，是构建一个：面向深度研究、信息提纯与认知探索的 AI Research Browser Runtime。

它是一种介于浏览器、搜索引擎、信息提纯系统、网页理解 Runtime、AI Research Runtime、Evidence System、知识获取引擎之间的全新产品形态。

它不是为了"访问互联网"，而是为了更深层地理解互联网。它不满足于搜索一个关键词、点击几个网页、阅读广告污染的页面、被算法推荐操控、被 SEO 污染结果包围、被网页模板和弹窗打断思考。

它希望做的是：重新组织互联网的信息结构。让互联网从混乱、商业化、噪声化、广告化，变成纯净、结构化、语义化、研究化、可认知化。

这并不是一个"普通工具"。它更像一种：认知基础设施。

# 二、产品定位

## 2.1 产品本质

本产品的本质，不是 Browser，也不是 Search，而是：Information Cognition Runtime，即信息认知运行时。

它负责：搜索互联网，理解互联网，净化互联网，重构互联网，组织互联网，提纯互联网，最终为 AI 和人类提供更高级的信息阅读体验。

## 2.2 核心关键词

### 第一层关键词（产品感知层）

纯净、洁白、轻快、语义、安静、透明、流动感。这一层决定：UI、动效、阅读体验、页面布局、字体排版、交互反馈、搜索体验、视觉风格。

产品不应具有传统搜索引擎那种广告化、门户化、信息拥挤、SEO污染的特征，而应更像一个无限延展的研究白板。

### 第二层关键词（功能体验层）

探索、深究、认知、无限、研究、推理、追踪、发现。这一层决定：Search Runtime、多轮搜索、搜索扩展、内容召回、Evidence Pack、高级阅读模式、深度研究体验、来源追踪、多网页联动。

### 第三层关键词（产品精神层）

窥探、贪婪、超越、极端召回、信息饥渴、认知扩张。这里并不是"危险"，而是对信息极端渴望。

它意味着：不满足于第一页结果，不满足于网页表层，不满足于SEO内容，不满足于搜索摘要，不满足于广告污染。而是尽可能召回、尽可能理解、尽可能提纯、尽可能组织。

# 三、产品愿景

## 3.1 互联网已经开始失控

现代互联网已经越来越SEO化、广告化、推荐流化、碎片化、商业化、模板化。

搜索结果越来越像营销平台，而不是知识入口。网页越来越像广告容器，而不是信息载体。用户获取真实信息的成本越来越高。因此，本产品希望：重新把互联网变成研究工具。

## 3.2 AI时代需要新的Browser Runtime

传统浏览器的核心是渲染HTML，而AI时代真正需要的浏览器核心是理解信息。

因此，未来浏览器不应只处理DOM，而应该处理语义、结构、证据、来源、可信度、信息关系。这也是本项目最核心的方向。

# 四、产品形态

## 4.1 第一阶段：Research Browser

第一阶段，我们不会优先做复杂Agent，而是优先构建：高级研究型浏览器 Runtime。即：Search + Crawler + Purifier + Semantic Reader + Evidence。

这一阶段的目标：让用户获得一种前所未有的互联网阅读体验。

## 4.2 第二阶段：Research Runtime

第二阶段，才会引入Agent、多轮搜索、自动研究、自动报告、任务分发、Evidence reasoning。但这些功能必须建立在第一阶段的信息基础设施足够强大的前提下。否则Agent只是在：垃圾信息上做推理。

# 五、核心功能体系

## 5.1 搜索召回系统

用户输入一个问题、一个关键词或一个研究方向，系统不会像传统搜索引擎那样只调用一个搜索源，而是同时调用多个搜索Provider，包括：SearXNG、Brave、DuckDuckGo、Wikipedia、GitHub、arXiv、Semantic Scholar、News、论坛、社区。

并在后台进行：多源召回、结果融合、质量排序、去重、来源多样化、动态扩展搜索。

## 5.2 动态搜索扩展

传统搜索：一个 query 对应一个结果页。而本系统：一个 query 自动拆解，生成多个 query，扩展搜索，融合结果。

例如，用户输入"为什么年轻人明知熬夜有害却无法停止？"，系统可能自动扩展：睡眠拖延、revenge bedtime procrastination、dopamine addiction、circadian rhythm、social media sleep research、adolescent sleep psychology。用户并不会直接感知这些复杂过程，但系统会在后台完成。

## 5.3 搜索结果界面

搜索结果界面必须：无限滚动、极简、高语义、低噪声。不应出现：广告、推荐流污染、无意义卡片、营销内容。搜索结果将被：智能排序、可信度加权、优质来源提升。

## 5.4 企业级高速爬取系统

点击任意网页后，系统不会直接把用户扔进原网页，而是启动高速网页获取Runtime，包括：HTML获取、资源发现、正文提取、结构分析、DOM净化、内容重建。目标：尽可能完整地理解当前网页。

系统支持：静态抓取、动态网页渲染、Playwright Runtime、网络资源监听、媒体资源发现，包括图片、视频、音频、文档、PDF、Markdown。

资源嗅探系统会自动发现：页面资源、媒体资源、OpenGraph资源、JSON-LD资源、懒加载资源、网络请求资源。用户可查看：当前网页包含的资源图谱。

## 5.5 广告与噪声过滤

系统会自动：去广告、去推荐流、去弹窗、去侧边栏、去营销区、去Cookie横幅、去订阅框，并保护正文、引用、代码块、图片、视频、链接。目标：正文保护优先。

## 5.6 DOM重构与双阅读模式

系统不是简单删除广告，而是：重新组织网页结构，包括段落重排、标题提取、字体优化、代码高亮、图片嵌入、视频嵌入、链接标注、引用整理，最终生成高级阅读模式。

用户可随时切换：原网页与Semantic Reading Mode，形成原始互联网VS净化后的互联网的对比。

## 5.7 Semantic Reader

本产品的阅读体验不是简单Markdown，而是：Semantic Reading Runtime。特点：自动结构化、语义段落、标题层级、重点高亮、引用标注、资源内联、上下文保留。

语义排版系统会自动分析：段落关系、文本密度、标题结构、代码块、引用块、列表、媒体区域，自动生成适合人类认知的阅读结构。

## 5.8 Evidence Runtime

系统不仅阅读网页，还会：提取证据、组织来源、关联段落、去重内容、标记引用，最终形成Evidence Pack，即一个可供 AI 和人类共同阅读的结构化证据包。

引用系统要求所有内容必须可追溯来源，包括：URL、原始段落、时间、来源网站、上下文。避免：AI幻觉、信息断裂、来源丢失。

# 六、未来方向

Agent Runtime：未来系统会支持AI Agent、多轮搜索、自动研究、自动补搜、自动整理、报告生成，但这不是第一阶段重点。

Local Knowledge Runtime：未来支持本地文件、PDF、DOCX、Markdown、知识库、本地搜索。

Distributed Search：未来可能研究去中心化搜索、本地索引、P2P索引。

# 七、产品气质

本产品不是喧闹的、广告化的、门户式的、营销式的。

而是：安静的、纯净的、冷白的、高速的、深度的。

用户体验应该像：进入一个无限延展的信息空间，而不是进入一个被广告污染的网页市场。

# 八、技术路线

### 第一阶段（当前）

核心：Search Runtime、Crawler Runtime、Purifier Runtime、Semantic Reader、Evidence Runtime。

### 第二阶段

核心：Agent Runtime、Research Runtime、多轮搜索、自动研究。

### 第三阶段

核心：Local Knowledge、Distributed Search、AI-native Browser Runtime。

# 九、最终总结

本项目最终并不是：一个搜索引擎，也不是：一个浏览器。

而是：一个面向深度研究、信息提纯与认知探索的 AI Research Browser Runtime。

它不满足于：展示互联网，而是希望：重新理解互联网、重新净化互联网、重新组织互联网、重新提纯互联网，并最终：把互联网重新变成人类与 AI 可以真正理解的知识空间。
